# 通用记忆插件

`memory` 使用统一的原始事件、记忆记录和来源关系，服务于日常交流、观看、游戏、学习、工作等场景。模型自由决定主题、标签、别称和关联；程序不预设人物字段、项目模板或唯一分类。

## 配置

```json
{
  "name": "memory",
  "enabled": true,
  "storageService": "storage",
  "shortTerm": { "enabled": true, "maxTurns": 8, "ttlMs": 1800000 },
  "store": { "enabled": true, "maxEntries": 5000, "eventRetentionDays": 30 },
  "maintenance": {
    "batchSize": 16, "extractEveryNEvents": 3, "flushAfterMs": 60000,
    "pollMs": 15000, "maxSourceChars": 24000, "maxContextChars": 32000,
    "maxTokens": 8192, "candidateLimit": 48
  },
  "retrieval": { "maxInject": 8, "maxPinned": 6, "maxContextChars": 12000, "minSimilarity": 0.45 },
  "embedding": {
    "enabled": false, "endpoint": "", "model": "", "apiKey": "", "proxy": "",
    "timeoutMs": 4000, "batchSize": 16
  },
  "questions": { "enabled": false, "maxQuestions": 30 }
}
```

`enabled` 控制整个插件，`store.enabled` 控制持久记忆的采集、维护与注入；关闭后已保存内容仍可查看。`shortTerm` 控制近期交流的查看与非核心对话调用的背景注入，不承担持久化。完整对话历史与压缩继续由核心 `conversation.history` 管理。

新配置推荐使用上面的字段。已有 `longTerm`、`work`、`practice` 配置仍能读取，其启用状态用于兼容推导持久记忆开关；它们的旧提取、分类和检索参数不再驱动运行流程。显式 `store.enabled` 优先。旧 `work.enabled=true` 会兼容开启通用提问；可用 `questions.enabled=false` 关闭。`memory.summary` 等已移除字段继续拒绝。

## 保存与维护

直接用户文字在接入时保存原文，并尽快触发后台提取，无需等待20轮对话。其他活动线索累计到事件数门槛或等待时间后处理；即使静默也能记录。只有带实际图片来源的视觉摘要进入记忆，影视台词、游戏聊天和设备音频继续标注为观察。宠物自己的回答、建议和记忆工具返回不作为新证据。

较长原文分段保存，不截断后续段落。短时间内同来源的重复背景文字去重，用户表达不按内容去重。来源队列在 SQLite 中持久化，重启后继续处理。存储临时失败时来源暂存在进程内，恢复后重试；该临时缓冲无法跨进程崩溃恢复。

模型返回 `upsert`、`archive`、`forget`、`discard` 与可选 `questions`。新增和更新必须引用本批来源，摘录必须逐字存在于原文。用户陈述、观察、推断分别标记；旧来源不能覆盖较新状态，观察不能覆盖用户确认，自动整理不能改写手动修正的内容。引用校验不能替代语义判断，因此不保证模型抽取永远正确。

记忆、全文索引、版本、来源关系和本批队列消费在同一事务中保存。失败保留原状态与待处理来源，并进行有上限的退避重试；上下文读取不触发提取重试。新到来源留给下一批。停止、模型或存储更新、清空、手动修改都拒绝旧请求的迟到写入。

每条记忆当前携带最多16条来源摘录，完整来源关系独立保存，避免反复确认让上下文无限膨胀。未被记忆或问题引用、已经处理的原始事件默认保留30天；引用过的来源和未处理来源不参加这项清理。达到条目容量时停止新增并保留来源，不自动淘汰重要内容。

## 召回

每轮根据当前输入召回，动态背景放入本轮消息，不改写稳定前缀，也不反复写入历史。常用背景由模型选择，受数量与字符预算限制。当前问题优先于整段旧聊天；历史记录可以主动查询，过期与归档内容不自动作为当前事实注入。

默认检索采用中文词语与二字词预处理的 SQLite FTS5、相关性排序和模型生成的别称/不同问法。重要性和时间不会让无匹配的普通记录绕过相关性门槛。没有相关结果时可以不注入。

要启用真正的向量语义检索，显式配置兼容 `/embeddings` 的服务。不会假定主对话接口支持 embedding，也不会默认复制其密钥。索引按批增量重建，以服务、模型和内容哈希隔离；查询使用独立超时和取消信号。失败退回全文检索。未配置 embedding 时，同义改写仍可能漏召回。

模型可通过 `memory.search` 和 `memory.read` effect 主动搜索和查看来源，结果进入后续回合；查询链最多两次，不阻塞 `decision.completed`。插件同时提供 `memory.search`、`memory.read` 服务。工具返回不再次提取为新事实。

## 查看、修正与忘记

菜单「记忆 → 查看当前记忆」展示模型生成的主题，支持搜索、主题筛选、分页、来源原文与版本查看。没有固定的人物、项目或经验页面。可修正任意记忆、调整是否经常需要记住，或删除记忆。

「整理」按候选数与字符预算分批覆盖全部当前记录，允许模型调整主题和检索表达。每批独立事务；后续批失败时，之前已提交的整理保留，失败批保持原状。它不强制压缩比例或编造新事实。

单条忘记先显示确认，删除对应内容、来源、历史、索引以及引用相同来源的记录。共享来源可能涉及多条记忆，因此可能一起删除。模型永久忘记或丢弃原文必须引用新的用户请求；外部资料不能授权删除。被删除内容的哈希用于阻止精确副本自动重建。未来用户用不同措辞重新提供类似内容仍需模型遵守其记忆意愿。

忘记会重置当前对话背景，避免刚删除的内容留在进程内的历史里。「清空全部记忆」删除全部记忆数据和旧版记忆副本。两者均保留独立的历史对话及原始请求/截图日志；如需删除这些记录，应使用对应插件的清理入口。

通用问题由模型根据实际交流产生，不固定盘问身份或工作。需要同时启用 `memory.questions.enabled` 和 `questions.enabled`。回答作为明确用户来源进入统一维护流程；删除提问记录不撤销已经形成的记忆，移除的问题不会自动按同一题目重建。

## 旧数据与验证

首次初始化将已有长期记忆、人物记录、项目/经验、待处理来源和旧提问历史导入新库，保留原确认等级；旧记录不会冒充新的用户陈述。旧事实与实践记录的历史版本作为历史记忆保留。迁移标记确保不重复导入；旧表仅用于迁移与遗留回归测试，运行入口不启动旧提取流程。历史对话、截图和请求日志不在记忆迁移范围内。

新实现检查：`node --test tests/adaptiveMemory*.test.js`。全量检查：`npm test`。

合成场景评测：`npm run evaluate:memory -- --live`，读取当前模型配置，在独立内存数据库中评测，默认输出 `docs/memory-evaluation.json`。它会调用模型，但不会打开或修改真实记忆。评测分数仅衡量列出的合成检查，不代表长期使用满意度。详见 [评测记录](../../../docs/memory-evaluation.md)。
