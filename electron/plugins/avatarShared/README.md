# 形象插件

`avatar-live2d` 和 `avatar-3d` 是独立的主进程插件，分别选择 `src/avatars/live2d.ts` 和 `src/avatars/mmd.ts` 渲染组件。宿主负责窗口、拖拽、右键菜单入口、指针坐标、气泡、IPC 和当前形象的选择，不直接引用 Cubism 或 Three.js。

## 配置与切换

配置放在根节点 `plugins` 数组中。同时只允许一个形象插件启用；两个都关闭时保留桌面窗口和其它插件。旧配置没有任何形象插件时，自动补上默认 Setsuna 配置。只配置 `avatar-3d` 时，不会自动启用 Live2D。

```json
[
  {
    "name": "avatar-live2d",
    "enabled": true,
    "modelPath": "assets/Setsuna_v081l_b/setsuna_psd2live_v001.model3.json",
    "iconPath": "assets/Setsuna_v081l_b/icon.png",
    "scale": 1.5,
    "verticalOffset": 50,
    "defaultExpression": "neutral",
    "idleMotion": { "group": "Thinking", "index": 0 },
    "clickMotion": { "group": "ReachStudy", "index": 0 }
  },
  {
    "name": "avatar-3d",
    "physicsEnabled": true,
    "enabled": false,
    "modelPath": "assets/【芙宁娜】/【芙宁娜】.pmx",
    "scale": 1,
    "verticalOffset": 0,
    "rotationY": 0
  }
]
```

切换到芙宁娜时，在同一次保存中关闭 `avatar-live2d`、开启 `avatar-3d`。配置更新会暂停决策、取消旧模型请求、清空本次进程内的对话上下文，再重载形象插件；持久记忆和历史记录继续保留。新的对话读取新模型的表情列表。形象配置不合法时保留上次有效配置；资源缺失或损坏时记录插件失败或在窗口显示加载错误。

`modelPath` 和非空 `iconPath` 必须是项目 `assets/` 下的相对路径；资源包目录结构须完整保留。URL 会逐段编码，支持中文、空格及 `【】`。`scale` 支持小数；`verticalOffset` 单位为窗口 CSS 像素，正值向下。3D 的 `rotationY` 单位为度。Live2D 的 `idleMotion`、`clickMotion` 可设为 `null` 关闭；默认表情和非空动作会按模型目录校验。图标归宿主托盘管理，插件通过 `iconPath` 提供。

## 当前模型支持

- **Setsuna_v081l_b**：保留 Cubism 物理、Thinking 待机、ReachStudy 点击动作和原生表情；Cubism Core 只在加载该插件时导入。
- **芙宁娜 PMX**：支持 `【芙宁娜】.pmx` 与 `【芙宁娜_荒】.pmx`。加载完整材质和贴图，修正 Windows 反斜杠路径；使用骨骼实现手臂放松、呼吸待机、招手与头部跟随，使用顶点 morph 实现自动眨眼和表情。提供 `neutral`、`smile`、`sad` 等语义表情以及模型原生 morph 的手动选择。程序动作不依赖额外动画文件。

3D 角色支持右键按住并拖动旋转：上下俯仰限制在 ±30°，水平可连续旋转任意圈数；旋转以身体中心为轴，松开后保持角度。右键单击仍打开菜单，超过拖动阈值后不弹菜单、不触发聊天。左键拖动仍移动桌宠窗口，左键单击仍触发原有点击动作和聊天。旋转手势使用指针捕获，鼠标离开窗口仍可继续拖动；失焦、取消或切换形象会终止当前手势。

启用 3D 插件时，托盘和右键菜单提供「角度回正」：点击后俯仰归零，水平恢复配置的初始朝向（`rotationY`，默认正面），并终止进行中的旋转手势。模型加载完成前该项不可用；Live2D 不显示此项。

3D 目前支持 PMX、预生成的 Three.js 骨骼关键帧和模型自带的刚体／关节物理，不包含 VRM/glTF、VMD 动画或通用布料模拟。Three.js 与类型固定在兼容 MMDLoader 的 0.170 系列；升级时需要同步迁移 MMD 加载器并重新验证模型。芙宁娜资源由 miHoYo 提供、观海改造，使用遵循资源包内说明；模型不提交到仓库。

3D 形象默认使用至少 640×720 的透明窗口（不超出当前屏幕工作区），较大的 `ui.windowWidth/windowHeight` 仍生效。相机同时留出全身、双臂展开与摘帽的空间；切换回 Live2D 时恢复普通窗口尺寸。窗口调整保持原来的右下角位置，并自动收进可用桌面范围。

## 芙宁娜常用动作

准备好本地 PMX 资源后，运行 `npm run motions:furina`。生成器读取实际骨骼位置、层级和臂长，将待机、招手、点头、摇头、思考、鞠躬、开心、鼓掌、摘帽致意、天鹅舞烘焙成 30 fps 的 Three.js AnimationClip JSON，保存到 `assets/【芙宁娜】/motions/`。天鹅舞为 16 秒的全身短舞：屈膝起势、踮脚、左右换重心与旁擦地伸腿，配合躯干转动和错开的肩肘腕波浪，最后双手回到身前。腿部按模型真实腿长和脚尖支点求解，并同时烘焙实际蒙皮使用的 D 骨骼。摘帽致意为 10 秒，抬手取帽、拿到身前鞠躬后戴回；帽体通过独立骨骼控制，其飘带物理约束改接随帽子移动的运动学锚点，防止摘下后仍被头部拉住。思考和鼓掌通过双骨骼 IK 计算肩、肘、腕姿势。常用动作保持双脚站立；天鹅舞额外驱动骨盆、腿与脚，以及中心骨的小幅位移；摘帽动作额外驱动帽骨的位置和旋转。所有片段都包含腿部归位轨道，支持中途切换平滑回到站姿；不覆盖头发、衣服的物理骨骼。生成过程在本地执行，无需在线动作生成服务。

`catalog.json` 声明可兼容的模型及动作；芙宁娜与荒版本共享这套核心骨骼。插件启动时自动发现相邻动作目录，右键「播放动作」即可使用；缺少目录时仍保留原有待机和招手。新增动作文件后重载形象或重启应用以刷新目录。一次动作结束后自动淡入待机，播放中也可切换或重播；点头等动作期间会减弱鼠标头部跟随，避免覆盖动作。物理继续在动作之后更新。

生成文件与模型一样属于本地 `assets/`，由现有构建流程复制；生成脚本保存在仓库内，可重复生成。替换模型或调整动作定义后需重新运行脚本。这些是程序化骨骼动作，不是在线 text-to-motion 服务生成的动作，也不是 VMD 文件。

## 头发与服饰物理

`avatar-3d.physicsEnabled` 为布尔值，默认 `true`，已有配置不填写也会开启。设为 `false` 后不加载 Ammo/WASM、不创建物理世界；保存配置会重载当前 3D 插件。该开关只影响 PMX 物理，Live2D 继续使用 Cubism 自带物理。

开启时使用项目所依赖的 Three.js 包内 Ammo/WASM 和 MMDPhysics，读取 PMX 的刚体及关节。默认采用适合桌宠的小幅摆动参数：以 130 Hz 固定步进、每帧最多追赶 6 步，关节求解 40 次迭代，位置修正系数为 0.05、柔顺系数为 0.01。每个渲染帧将动态刚体的求解位移限制在模型高度的 0.8% 以内、旋转限制在 6° 以内；高帧率按帧间隔缩小预算，多次物理追帧共享单帧预算，超限时同步修正 Bullet 变换并清除速度与外力。运动学刚体仍随主动动作移动。保留 PMX 的弹簧与阻尼，服饰刚体只与模型允许的身体碰撞组发生碰撞，减少密集服饰互撞导致的抖动；参数调整不改写 PMX 资源。

头部跟随幅度较小，招手以平滑曲线进入和退出，避免突然拉动头发和衣袖。模拟持续运行，让动作结束后的摆动自行衰减，并允许 Bullet 在低速时自然休眠，没有固定两秒后冻结姿态的处理。物理使用模型自身坐标，旋转视角、重置视角、呼吸展示和移动桌宠窗口均不会甩动衣服。初始化会预热模拟，长时间暂停后会重新稳定；卸载会清理 Bullet 原生资源。

## 宿主契约和生命周期

主进程插件通过 `context.avatar.register(descriptor)` 提供形象，返回取消注册函数；插件在 `start` 注册，在 `stop`/`dispose` 释放。宿主也追踪注册，激活回滚或卸载时自动清理。描述包括渲染类型、资源 URL、布局参数、表情列表和动作列表；具体动作标识由插件解释。动作和表情菜单由插件通过 `context.menu` 提供。

宿主 `createAvatarHost` 管理一个当前提供者和递增 `revision`。渲染进程通过受控 IPC 获取快照、订阅变更，并在模型和贴图加载完成后确认 `revision`。动作命令只接受当前插件声明的 ID，并附带代次；迟到的就绪通知和旧命令被忽略。首次快照和变更通知交错时，也按代次保留最新配置。

渲染组件统一实现 `AvatarRenderer`：`setExpression`、`playMotion`、`focus`、`getHeadAnchor`、`hitTest`、`onTap`、`resize` 和 `dispose`。每次加载有独立的 AbortSignal；被替换的异步加载完成后会释放资源，不能覆盖新形象。已加载形象卸载时立即清理计时器、模型、纹理、渲染器和画布。Live2D 与 Three.js 按需导入，只有当前形象的渲染循环运行。
