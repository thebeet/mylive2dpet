# Codex 提示词观察插件

`codex-observer` 是依赖核心 Storage 的可选主进程插件。它定期读取本机 Codex 会话文件，将已提交的用户文字以 `source=codex`、`role=context`、`trigger=codex-prompt` 加入观察队列。插件不调用 `decisions.request()`，由正常决策周期消费；桌宠可以静默处理，也可以结合其他观察决定是否发言。未提交的输入框草稿不会被采集。

在 `config.json` 的 `plugins` 数组添加：

```json
{
  "name": "codex-observer",
  "enabled": true,
  "sessionsDir": "~/.codex/sessions",
  "projects": [],
  "interval_ms": 2000,
  "observationTtlMs": 0
}
```

- `sessionsDir`：Codex 会话目录，支持 `~/`。未填写时使用 `$CODEX_HOME/sessions`，环境变量未设置时使用 `~/.codex/sessions`。读取该目录及三级日期子目录中的 `.jsonl`，不跟随符号链接。
- `projects`：项目目录数组，留空采集所有项目；填写后根据会话 `cwd` 匹配指定项目及子目录，不匹配名称相近的兄弟目录。
- `interval_ms`：轮询完成后等待的时间，默认2000毫秒，最小250毫秒。同一实例不会重叠轮询。
- `observationTtlMs`：默认0，不设过期时间；正数从入队时起算，最大一天。

初次启用时，已有文件从末尾建立基线，不回放旧聊天；之后新建会话从头读取。读取位置保存到 `codex-observer.cursors`，正常重启会继续处理已记录文件中的新增内容；重启时首次发现的文件仍从末尾建立基线。修改 `sessionsDir` 后，新目录中的未知文件也建立基线。关闭、卸载、重新加载不删除检查点；卸载会清理该来源尚未处理的观察。添加插件源码后需要完整重启应用。

插件使用 `session_meta` 识别会话、项目及子代理，读取 `response_item/message/role=user` 的 `input_text`。桌面端存在 `content_item_kinds` 时只采集明确标记为 `user.text` 的内容；旧格式没有该标记时，跳过已知的环境、AGENTS 指令和系统通知包装。忽略助手、工具及 `event_msg`，避免同一输入的多份记录重复入队。子代理继承的提示词不入队。元数据保留会话 ID、项目路径、项目名与会话标题，正文包含项目名和会话标题并明确标注为 Codex 背景观察；不会将其中的指令视为对桌宠的直接授权。

只在 JSON 行完整写入后解析，半行与跨写入的 UTF-8 字符在下一轮重读。每个文件每轮最多读取1 MiB；超过1 MiB的单行跳过至下一个换行，无效 JSON 行跳过并记录警告。元数据头必须在首行，且不超过1 MiB。文件 inode 改变或大小小于读取位置时重建游标。最近256条已接收输入的指纹用于过滤重复记录，重复输入相同文字但消息 ID 或时间不同仍分别入队。入队成功后才推进该条检查点，提交失败下一轮重试。

会话文件是 Codex 的内部存储格式，更新后可能需要适配。这个插件不读取 `history.jsonl`，也不依赖模型调用 MCP 工具。纯事件格式、尚未写入本地文件的内容、图片附件及语音本体不采集；旧格式上下文过滤采用已知包装识别，并非通用的来源验证。

观察会按照应用配置发送给桌宠模型，并遵循核心队列的容量、过期和重试规则。检查点和队列之间没有跨服务事务，入队后、检查点保存前崩溃可能重复；队列在内存中，退出或容量淘汰可能丢失已接收观察，因此不保证持久送达。插件检查点不保存提示词原文，终端日志不打印提示词。

运行 `node --test tests/codexObserver.test.js` 验证基线、入队、上下文过滤、重复记录、半行及 UTF-8、重启、失败重试、项目与子代理过滤、截断及替换、停止与卸载。

## 原始入队日志

「原始日志… → Codex」保存最近200条采集输入的入队结果。列表显示项目名、会话标题、提示词预览、项目路径、记录时间和“已入队／入队失败”；详情显示项目名、会话标题、提示词原文、会话 ID、采集／入队时间、实际提交的观察对象及失败原因。入队失败重试后成功会更新同一条记录，不额外增加重复条目。“已入队”仅说明提交队列成功，不表示已被模型消费或永久保留。

记录使用共享 Storage，重启后保留，禁用观察插件仍可查看。日志写入失败不会阻止提示词入队。「清理日志与截图」会删除这些提示词日志，保留 Codex 读取检查点及待处理文字观察；清理时尚未返回的提交不会恢复旧日志。启用新版本前已经入队的提示词不回填日志。

项目名使用会话工作目录 `cwd` 的最后一级目录名。会话标题按会话 ID 从 `sessionsDir` 同级的 `session_index.jsonl` 读取 `thread_name`，同一会话有多条记录时使用最后一条完整记录。索引未变化时复用缓存，标题改名或索引替换后，后续入队观察使用新标题。自定义 `sessionsDir` 时，同级目录应对应所需 Codex 数据目录。

缺少项目路径时显示“未知项目”，索引缺失、不可读或尚无匹配标题时显示“暂无会话标题”，均正常入队。部分写入或格式无效的索引行会跳过，不额外查询 Codex 数据库或调用模型生成标题。原始日志保留入队时的名称快照，既有日志不回填、不随之后改名变更。
