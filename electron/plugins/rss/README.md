# RSS／Atom 感知

`rss` 是可选的主进程插件，依赖核心 Storage，不需要浏览器扩展或额外服务。在 `config.json` 的 `plugins` 中添加：

```json
{
  "name": "rss",
  "enabled": true,
  "feeds": [
    { "name": "项目动态", "url": "https://example.com/projects.atom", "proxy": "http://127.0.0.1:8899", "interval_ms": 60000 },
    "https://example.org/feed.xml"
  ],
  "interval_ms": 300000,
  "timeoutMs": 20000,
  "emitOnFirstFetch": false,
  "observationTtlMs": 0,
  "maxContentChars": 12000,
  "maxResponseBytes": 2097152
}
```

- `feeds` 支持 HTTP(S) 地址字符串或 `{url, name, proxy, interval_ms}`；每个地址必须唯一。
- 每个 feed 的 `proxy` 是该订阅源的 HTTP(S) 代理地址，省略或留空直连；字符串形式的订阅地址也直连。不同代理与直连使用隔离的 Electron session，相同代理复用配置，不修改核心模型的代理。RSS 插件根节点不支持 `proxy`。
- 启动后立即检查所有订阅。每个 feed 可设置自己的 `interval_ms`，省略时使用插件全局的 `interval_ms`（默认5分钟）；两处均允许1000～86400000毫秒。上例项目动态每分钟检查，字符串形式的订阅每5分钟检查。
- 每个订阅的间隔从自身检查完成时起算；使用一个定时器唤醒最近到期的订阅，只检查已经到期的源。请求串行处理，不重叠；慢请求可能推迟其他源的检查，恢复后检查一次，不集中重放错过的轮询。
- 默认第一次成功读取只建立基线，不播报已有条目。设 `emitOnFirstFetch=true` 可将首次读取的现有条目也提交观察。
- ID 优先取 Atom id／RSS guid，其次链接，最后标题与发布时间；同一 ID 的标题、内容等变化也视为更新。条目指纹覆盖完整解析内容，观察正文按 `maxContentChars` 截断。
- 支持 RSS 2.0、RSS 1.0 RDF、Atom、CDATA 和 XHTML 正文，兼容 GitLab Atom 中未自闭合的 `br`／`hr`／`img`／`wbr` 标签。HTML 正文转成纯文字，不下载文章网页或附件；订阅只提供摘要时观察也只有摘要。
- 使用 ETag／Last-Modified 条件请求，304 不生成观察。HTTP、解析、超时或队列提交失败只记录警告，下轮继续；失败的首次读取不建立基线。
- `maxResponseBytes` 限制每个响应的字节大小；`timeoutMs` 覆盖网络请求和响应读取。

## 观察与记忆

每个新增／修改条目生成 `source=rss`、`role=context`、`trigger=rss-update` 的文字观察。JSON 正文包含订阅名称、脱敏地址、标题、文章链接、作者、发布／更新时间、内容、变化类型和截断标记。配置 URL 中 token／key／auth／secret／password 等参数不会随观察传给模型，日志中的对应值也会脱敏。

插件只提交队列，不主动请求决策，不直接显示气泡或播放语音。条目等待正常决策，模型可以静默处理或结合当前情境回应；关闭自动决策时需要手动触发。`observationTtlMs=0` 不设置过期时间，正数从实际入队起算。观察仍遵守共享队列容量限制，需要时可配置 `observations.perSource.rss`。

订阅内容属于外部资料，不是用户直接说的话；不会作为用户人物关系画像的原始证据，也不会进入项目经验来源队列。主对话仍可参考本轮条目及已完成的对话历史。

## 持久化与生命周期

订阅基线、已接收条目指纹和 HTTP 缓存验证器存入 `rss.feeds` 集合，重启后继续检测离线期间的新条目与修改。地址改变视为新订阅源；禁用／移除插件保留检查点，重新启用相同地址不会重新播报旧条目。检查点随已见条目数量增长。

修改某个 feed 的代理或间隔会触发插件配置重载，相同订阅地址的检查点继续保留。

每条观察成功入队后才保存指纹；后续条目失败时不会重放此前已成功记录的条目，本轮 HTTP 验证器只在全部处理成功后更新。原子性不跨越观察队列与 Storage：提交成功后、指纹保存前崩溃可能重复；观察队列在进程内，提交后尚未处理的条目可能因退出或容量淘汰丢失，不保证持久送达。插件卸载会取消网络请求、等待已经开始的提交保存检查点，并清理尚未处理的 RSS 观察。

离线补偿仅覆盖订阅源恢复时仍提供的条目，不抓取已从订阅源窗口中移除的历史条目。不会重放手动清理原始日志之前已经记录的更新。

## 原始获取日志

右键菜单「原始日志…」中的「RSS」页展示获取时间、订阅名称、每个 feed 的代理与实际间隔、HTTP 状态及选定响应头、耗时、原始响应正文、全部解析条目和逐条入队结果。首次基线、无变化的成功检查、304、HTTP／解析／入队失败和取消也会记录。正文及条目使用纯文字显示；响应正文中的配置访问令牌同样脱敏，不保存认证 Cookie。

`rss.history` 在共享 SQLite 中保存最近200次获取记录，重启保留。日志中的解析正文不受观察的 `maxContentChars` 截断，响应读取仍受 `maxResponseBytes` 限制。列表分页不向界面发送原始正文，选择记录后再读取详情；RSS 插件禁用或移除后仍可查看既有日志。

「清理日志与截图」同时删除 RSS 获取记录，保留 `rss.feeds` 更新检查点及已经入队的 RSS 观察；清理期间的迟到响应不会重新写入旧日志，也不取消正在获取的订阅。日志保存失败不会阻止观察入队。

运行 `node --test tests/rss.test.js` 检查解析、首次基线、新增／修改、重启、条件请求、代理、令牌脱敏、队列失败、响应限制及生命周期。
